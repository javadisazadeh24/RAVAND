# معماری RAVAND Management OS — پیشنهاد فاز ۱

## تصمیم‌های اصلی و دلیل
1. **PostgreSQL برای هر دو حالت (محلی و ریموت).** با Docker Compose روی کامپیوتر خودتان هم همان دیتابیس سرور اجرا می‌شود. دلیل: SQLite در شروع ساده‌تر است، اما دو «گویش» دیتابیس یعنی مهاجرت دردسرساز و رفتار متفاوت. یک Compose واحد این مشکل را حذف می‌کند.
2. **Next.js 14 (App Router) + TypeScript + Prisma + نشست خودکار با JWT (jose) و bcrypt.** یک کد برای UI و API؛ مجوزها سمت سرور در `actions.ts` و `perm.ts` بررسی می‌شوند. به‌جای Tailwind از CSS ساده با توکن‌های برند استفاده شد تا وابستگی و پیکربندی کمتر شود (تغییر نسبت به پیشنهاد اول).
3. **RBAC متمرکز:** یک تابع `can(user, action, resource)`؛ دسترسی مالی با فلگ جدا (`canSeeFinance`) و پیش‌فرض بسته.
4. **Audit log از همان ابتدا:** هر نوشتن روی Task/Project/Report از یک لایه‌ی سرویس عبور می‌کند که before/after ثبت می‌کند. حذف‌ها soft-delete (`deletedAt`).
5. **تاریخ:** ذخیره Gregorian (UTC)، نمایش Jalali با `Intl` (`fa-IR-u-ca-persian`) و تبدیل در یک ماژول واحد؛ منطقه‌ی زمانی Asia/Tehran.
6. **پول:** عدد صحیح (BigInt) + `currency` (تومان/ریال)؛ هرگز float. درآمد قراردادی/صادرشده/دریافت‌شده در ماژول مالی جدا نگه داشته می‌شود.
7. **پیشرفت گزارش‌شده ≠ پیشرفت تأییدشده:** در جدول Report دو فیلد جدا.
8. **فایل‌ها** روی دیسک (`UPLOAD_DIR`، volume داکر)، متادیتا در دیتابیس. GitHub فقط کد.
9. **پشتیبان‌گیری:** اسکریپت `pg_dump` زمان‌بندی‌شده + دستور restore مستند (فاز ۶ تست می‌شود).
